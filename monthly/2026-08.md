## 💡 Learned

- **Technical:** Repository .git/info/exclude affects only local tracking, not remote — use for personal ignores without polluting .gitignore.

- **Technical:** Pipeline.yml, manifest.yml, Jenkinsfile are canonical files for Forge CI/CD — these must be present and correct for pipeline automation.

- **Technical:** CCM-UI Stage and ITF deployments are nearly identical with only minor config differences — can be managed in parallel to reduce cycle time.

- **Technical:** Custom Copilot agents improve focus and productivity for recurring tasks like Data Table and Popover development — can scale this pattern across team.

- **Process:** PLLs and implementation plans must be verified in detail; no assumptions acceptable — errors here cause deployment issues later.

- **Process:** Create a dedicated tracking group per CRQ (with CRQ name) before deployment — centralizes validation, communication, and follow-up.

- **Process:** Validation documentation is essential audit trail — captures what was tested, edge cases, and known limitations for rollback decisions.

- **Process:** Knowledge transfer sessions before significant deployments reduce post-deployment surprises — make KT a mandatory gate.

- **About the team/product:** Component hierarchies require explicit documentation — one component using another doesn't automatically inherit all props/methods.

- **About the team/product:** Repository migrations require end-to-end coordination across tools, teams, and access management — persistence and clear escalation resolve blockers.
